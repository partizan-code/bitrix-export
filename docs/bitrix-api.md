# Документация Bitrix24 через MCP

[Все документы](README.md) · [Архитектура](architecture.md) · [Сверка запросов](bitrix-api-audit.md)

## Назначение и подключение

Для разработки интеграции подключён официальный MCP-сервер документации
Bitrix24 `b24-dev-mcp`. В текущей сессии его инструменты доступны с префиксом
`b24_dev_mcp`; имя подключения в другой среде может отличаться.
Сервер предоставляет справочные сведения и не читает данные рабочего портала.
Его использование не заменяет проверку прав вебхука и не разрешает запуск
выгрузки. Python-приложение продолжает обращаться к порталу через `B24Client`;
MCP используется агентом при разработке, а не как зависимость приложения.

Адрес сервера — `https://mcp-dev.bitrix24.tech/mcp`, транспорт — Streamable HTTP.
Ключи портала для чтения документации не нужны. Подключение настраивается
в среде разработчика; секреты и локальную конфигурацию Codex в репозиторий
не переносим. [Официальная инструкция MCP](https://apidocs.bitrix24.ru/ai-tools/mcp.html).

## Инструменты и порядок сверки

| Инструмент MCP | Назначение |
|---|---|
| `bitrix_search` | Поиск метода, события или статьи; фильтры `doc_type` и `limit` |
| `bitrix_method_details` | Контракт метода: параметры, результат, ошибки и примеры |
| `bitrix_event_details` | Описание события |
| `bitrix_article_details` | Общая статья документации |
| `bitrix_app_development_doc_details` | Материалы по разработке приложений |

Здесь приведены имена инструментов в текущей сессии; официальная страница
MCP использует написание через дефис, например `bitrix-search`.

Перед изменением запроса или разбора ответа:

1. Найдите метод через `bitrix_search`, затем прочитайте его карточку
   `bitrix_method_details`. Например, для звонков ищите
   `crm.activity.call.getTranscript` и проверяйте не только `activityId`,
   но и структуру `result`.
2. Сверьте параметры, регистр и типы полей, фильтры, сортировку, scope/права,
   формат результата, курсоры страниц, ограничения и ошибки.
3. Проверьте версию REST и адрес вызова. Одинаковое имя метода ещё не означает
   одинаковый контракт в старом REST и REST 3.0.
4. Зафиксируйте существенные допущения и ссылку на источник в техническом
   описании задачи. Проверяйте реализацию изолированными моками согласно
   [testing.md](testing.md); живой портал требует отдельного разрешения.

## Ограничения источника

Сверка 24 ноября 2026 года показала: поиск иногда выдаёт нерелевантные методы,
карточка `tasks.task.list` смешивает сведения разных версий REST, а карточка
`crm.status.list` ссылается на частный учебный пример. Некоторые ссылки MCP
также ведут на старый путь страницы. При таком результате уточняйте поиск,
читайте карточку известного метода и официальную страницу нужной версии.
Нерелевантный результат поиска не доказывает отсутствие метода.

Если MCP недоступен или сведения расходятся, явно укажите ограничение
и используйте официальный справочник `apidocs.bitrix24.ru`. Не заменяйте
непроверенные поля догадками и не меняйте версию API автоматически.

Для клиента отдельно проверяйте [лимиты REST](https://apidocs.bitrix24.ru/limits.html),
[batch](https://apidocs.bitrix24.ru/settings/how-to-call-rest-api/batch.html)
и [выборку больших объёмов](https://apidocs.bitrix24.ru/settings/performance/huge-data.html).
Текущее состояние запросов и предлагаемый порядок исправлений приведены
в [отчёте сверки](bitrix-api-audit.md).
