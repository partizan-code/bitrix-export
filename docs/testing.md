# Изолированные проверки выгрузки

[Все документы](README.md) · [Настройка](setup.md) · [Архитектура](architecture.md)

После [установки окружения](setup.md#окружение-и-доступ):

```text
mise run test
```

Задача выполняет `uv run --locked python -B -m unittest discover -s tests -v`.
Команда одинакова для macOS, Linux и Windows. Используются стандартный
`unittest` и уже необходимые приложению `requests` и `loguru`; отдельный тестовый
фреймворк не нужен. `-B` запрещает создание `__pycache__`. CI пока не настроен.
Для REVIEW / ANALYSIS / PLANNING тесты требуют явного запроса и готовой `.venv`:
используйте `mise exec -- uv run --no-sync python -B -m unittest discover -s tests -v`,
чтобы не менять зависимости или lock-файл. `mise run test` может синхронизировать окружение.

## Ruff

Ruff входит в группу зависимостей `dev`. Проверки всего проекта:

```text
mise run lint
mise run format-check
```

Задачи не исправляют код. Для проверки отдельных файлов используйте команды
ниже; в read-only режиме замените `uv run --locked` на `uv run --no-sync`.

Для диагностики скачивания аудио:

```text
mise exec -- uv run --locked python -B -m unittest discover -s tests -p test_diag_download.py -v
mise exec -- uv run --locked ruff check --no-cache scripts/diag_download.py tests/test_diag_download.py
mise exec -- uv run --locked ruff format --check --no-cache scripts/diag_download.py tests/test_diag_download.py
```

`test_diag_download.py` подставляет config до импорта модулей проекта:
реальные config/.env не читаются. HTTP и curl заменены моками, сеть/DNS и
неподменённые subprocess запрещены. Логи пишутся в TemporaryDirectory.
Проверяются частичные данные при тайм-ауте, предел 64 КиБ, Range/редиректы,
пустой/HTML-ответ, закрытие ресурсов, сохранность общих логов, атомарное
завершение диагностического лога и исключение секретов из его содержимого.

При установленном Ruff проверка линтинга и форматирования модулей,
затронутых изменением алгоритма страны:

```text
mise exec -- uv run --locked ruff check --no-cache config.py export_llm.py sync.py scripts/refresh_names.py tests/test_export.py
mise exec -- uv run --locked ruff format --check --no-cache config.py export_llm.py sync.py scripts/refresh_names.py tests/test_export.py
```

Для отдельного импортёра ZIP → SQLite:

```text
mise exec -- uv run --locked python -B -m unittest discover -s tests -p test_import_snapshot.py -v
mise exec -- uv run --locked ruff check --no-cache import_snapshot.py scripts/import_snapshot.py tests/test_import_snapshot.py
mise exec -- uv run --locked ruff format --check --no-cache import_snapshot.py scripts/import_snapshot.py tests/test_import_snapshot.py
```

Для структурированной базы из JSON/JSONL:

```text
mise exec -- uv run --locked python -B -m unittest discover -s tests -p test_source_sqlite.py -v
mise exec -- uv run --locked ruff check --no-cache source_sqlite.py scripts/source_sqlite.py tests/test_source_sqlite.py
mise exec -- uv run --locked ruff format --check --no-cache source_sqlite.py scripts/source_sqlite.py tests/test_source_sqlite.py
```

Для накопительной базы конечных карточек ZIP:

```text
mise exec -- uv run --locked python -B -m unittest discover -s tests -p test_snapshot_sqlite.py -v
mise exec -- uv run --locked ruff check --no-cache parse_snapshot.py snapshot_sqlite.py scripts/snapshot_sqlite.py tests/test_snapshot_sqlite.py
mise exec -- uv run --locked ruff format --check --no-cache parse_snapshot.py snapshot_sqlite.py scripts/snapshot_sqlite.py tests/test_snapshot_sqlite.py
```

Намеренные широкие перехваты ошибок при обработке отдельных сущностей,
загрузке необязательных справочников и выборе резервного режима отмечены
точечными `noqa: BLE001` с пояснениями: такие сбои не должны прерывать
обработку остальных данных.

## Результат проверки на Windows

На Windows с Python 3.12.16 (23 ноября 2026 года) `mise run setup`, повторная
синхронизация окружения, импорты зависимостей и `mise run --dry-run start`
проверены успешно. Сам бот и рабочие API не запускались.

После исправлений все 91 тест проходят; Ruff не находит нарушений линтинга,
форматирование всех 43 Python-файлов проходит проверку. В этой сессии ярлык
`mise.exe` был недоступен, поэтому проверки выполнены напрямую через готовые
`.venv/Scripts/python.exe` и `.venv/Scripts/ruff.exe` без установки зависимостей.
Подмена времени ограничена модулем
`sync`: форматирование `datetime` для имён файлов и идентификаторов снимков
использует штатные шаблоны без двоеточий. SQLite-соединения в тестах закрываются
явно; сведения о платформе в диагностическом тесте подменяются, чтобы Windows
не запускала служебные подпроцессы. Проверки на macOS/Linux не выполнялись.

## Изоляция

`test_bot.py` подставляет config, aiogram и настройки логирования до импорта бота,
использует временные файлы, запрещает сеть/DNS и заменяет `Popen` моками.
Проверяются удержание блокировки при проверке PID и запуске, отказ от повторного
запуска, атомарная публикация PID и остановка процесса при ошибке записи.
Асинхронные вызовы подменены немедленно завершающимися моками: цикл событий
с локальными сокетами и настоящий Telegram не запускаются.

`script_utils.load_script` загружает служебные команды из `scripts/` по пути.
Проверки CLI SQLite используют эти точки входа, а проверки схем и транзакций —
корневые библиотечные модули. Команды обновления имён и восстановления реестра
загружаются после подстановки искусственного config.
Отдельный сценарий запускает семь служебных точек входа через `__main__`:
диагностика API использует поддельный клиент, восстановление — временный store,
остальные команды проверяются через `--help`.

[tests/test_export.py](../tests/test_export.py) подставляет искусственный
модуль `config` **до** импорта модулей проекта. Настоящий `config.py` и `.env`
не читаются; окружение процесса временно очищается. Каждый тест использует
свой `TemporaryDirectory` для data, raw, export, audio и transcripts.
Обычные тесты отключают вывод Loguru; проверки логирования пишут оба файла
исключительно в тот же временный каталог.

Синтетический клиент заменяет `B24Client` при запуске `sync.main`, но сбор
источников, нормализация, рендер, store, registry, manifest и ZIP выполняются
настоящим кодом проекта. Неизвестные методы синтетического API дают ошибку.
Низкоуровневый клиент отдельно проверяется с подменой HTTP-ответов.

Для загрузки пользователей проверяются восстановление после сетевого сбоя
в пределах повторов `B24Client`, передача окончательной ошибки без повторного
запуска всей загрузки и сохранность прежнего кэша при сбое. Эталоны полного
и инкрементального снимков сохраняют формат карточек, имена аудио/транскрипций
и совместимые `null`-поля звонков после удаления веток `recording_url/stat_id`.

Проверки истории сессии в `test_export.py` используют страницы без сети:
несколько страниц с `LAST_ID/LAST_DATE` и фиксированным `SESSION_ID`, короткую
и пустую последнюю страницу, объединение пользователей, дубли ID разных типов,
числовую сортировку, неверные и повторяющиеся курсоры, смену сессии,
отсутствующий `hasNextPage`, предел страниц и сбой API на первой и последующих
страницах. Проверяется передача исходной ошибки без других API-вызовов.
Интеграционные сценарии подтверждают `partial` в manifest, сохранение ID
ошибки в state, продолжение остальных сущностей и повтор закрытой сделки
в следующем инкременте. Рабочий портал и предыдущие сессии этим не проверяются.

Скрипт сравнения всех сессий проверяется в том же `test_export.py` на моках:
пагинация списка, годовые окна с дробными границами, дробление до предела
offset, слишком плотное окно, повтор страницы, бюджет вызовов, чтение явного
SESSION_ID с проверкой chatId, старые и свежие добавления, новые привязки
чатов, отказ тарифа/прав и сохранение сообщений, не вернувшихся из API.
Проверяется побайтовая сохранность исходных файлов, повторное использование
загруженной сессии, отсутствие секретов в отчёте и режим плана без API/записи.

Аудит процесса запрещает сетевые подключения, DNS, subprocess, чтение
настоящего config/.env и основные файловые операции записи вне временного
каталога. Отдельный тест проверяет срабатывание защиты. Транскрибация через
AssemblyAI проверяется через моки.
Проверки следует запускать отдельным процессом указанной командой: audit hook
Python действует до завершения процесса.

[tests/test_import_snapshot.py](../tests/test_import_snapshot.py) использует
только стандартную библиотеку и искусственные ZIP/SQLite в собственном
`TemporaryDirectory` каждого теста; сетевые подключения запрещены моком.
Импортёр не зависит от `config.py`, `.env` или модулей API. Проверяются
точность байтов UTF-8/CRLF, различение сделок и лидов, история и частичные
снимки, повтор после перепаковки, конфликт ID, откат при ошибке записи,
некорректные архивы, сохранность чужой БД и коды завершения CLI.

[tests/test_source_sqlite.py](../tests/test_source_sqlite.py) строит искусственный
store/registry/manifest и метаданные по структуре рабочих JSON/JSONL.
Запись разрешена только в собственные временные файлы; сеть запрещена моком,
`config.py` и `.env` не используются. Проверяются отдельные колонки сырых
и расшифрованных полей, вложенные массивы, actor/ответственный, точное время,
история, частичный статус, новые поля, повторы/конфликты, согласованность
registry, изменение источников при чтении и транзакционный откат колонок/строк.
Эти проверки не означают сверку локального store с серверными архивами.

[tests/test_snapshot_sqlite.py](../tests/test_snapshot_sqlite.py) проверяет
отдельные колонки полей, время/порядок/типы касаний, различие автора и
ответственного, переиспользование версий, добавление/исправление/исчезновение
событий, одинаковые сообщения в одну минуту, новые и повторяющиеся подписи,
многострочные значения/имена, CRLF, точное восстановление карточек,
повторы/конфликты, чужие БД и транзакционный откат колонок и данных.
Только стандартная библиотека и собственные временные ZIP/SQLite, сеть
запрещена моком. Интеграция после сборки ZIP и сохранность ZIP/state при ошибке
SQLite дополнительно проверяются синтетическим прогоном в `test_export.py`.

## Что проверяется

- Полный и инкрементальный снимки сделок и лидов, в том числе с одинаковыми ID.
- Активные, завершённые и технические группы; отключённые группы и источники.
- Actor отдельно от ответственного, история стадий, все типы касаний,
  имена и пользовательские поля.
- Перенос закрытых из store, добор из registry, несовпадение схемы,
  отсутствие артефакта и оба значения `REEXPORT_CLOSED_ON_CHANGE`.
- Служебная страна по воронке сделки / источнику лида, исключение «Кухни ON+OFF»,
  `UNKNOWN` для неизвестных значений, сохранность исходного поля «Страна» и
  формата карточек. Пересчёт страны при переносе из store и `refresh_names`.
- Отсутствие добора старых закрытых в full; пустой результат без ZIP.
- Продолжение после ошибки сущности и повтор её ID в следующем инкременте.
- Лимиты и ID из config, сохранность state/registry в ограниченном запуске,
  переход из incremental в full при отсутствии state, отказ при передаче
  аргументов запуска до создания API-клиента и файлов выгрузки.
- Резервный способ чтения чатов, фильтрация служебных сообщений,
  пустые папки в ZIP и отсутствие JSONL внутри архива.
- Транскрипция через AssemblyAI, настройки отключения, кэш, вызовы через моки
  и переход с прямой ссылки на загрузку файла.
- Метаданные, отдельные кэши сделок/лидов, сохранность старого кэша и удаление
  временного файла при ошибке сериализации или `os.replace`.
- `refresh_names.py --offline` и восстановление отсутствующей записи registry
  исключительно на синтетических данных.
- Пагинация списков, сетевой сбой, HTTP 429, `QUERY_LIMIT_EXCEEDED`, исчерпание
  повторов и передача тайм-аута HTTP-клиенту.
- Профиль времени: вложенные замеры и исключения, сброс между запусками,
  различие логических API-вызовов, HTTP-попыток и повторов, отдельный учёт пауз,
  этапы синтетического прогона, кэш транскриптов и отсутствие содержимого
  карточек в сводке. Само профилирование не меняет артефакты снимков.
- Уровни и дописывание файлов Loguru, повторная настройка без дублей,
  предупреждения/ошибки библиотек, маскирование секретов в цепочке исключений,
  код выхода процесса и ошибки транскрибации с ID звонка.

## Сравнение с исходной версией

SHA-256 двух сценариев — полного снимка и следующего инкремента — первоначально
сняты до удаления лишнего кода и обновлены при смене алгоритма страны:
источник «Сайт» без страны теперь даёт `UNKNOWN` у лидов вместо `RB`.
Они проверяются в `test_full_snapshot` и
`test_incremental_snapshot` после содержательных проверок ожидаемых значений.
Время фиксировано, абсолютный путь временного каталога заменяется маркером.
При исправлении подмены времени эталоны обновлены только из-за штатных имён
файлов и `export_id`: обратная замена новых меток на прежний общий STAMP
в сериализованных артефактах дала оба прежних SHA-256 без других изменений.
После перехода на AssemblyAI эталоны обновлены: изменился источник текста,
появились файлы его кэша и исчезли запросы прежнего источника из трассы API.
Сравнение с воспроизведённым прежним поведением подтвердило, что остальные
артефакты и формат карточек сохранились.
В тестах фиксирована зона UTC+03:00 без зависимости от системной базы часовых
поясов; переводы строк в содержимом ZIP приводятся к LF.
В сравнение входят все созданные файлы, трасса методов/параметров API и
распакованное содержимое ZIP, включая имена пустых папок. Байтовое представление
самого ZIP не сравнивается из-за служебных меток времени файлов.

При изменении результата сначала исследуйте отличие; замена хэша сама по себе
не является исправлением. Для намеренного изменения формата нужно проверить
содержимое артефактов, согласовать контракт и только затем обновлять эталон.

Проверки не подтверждают доступность живого портала, реальные форматы всех
версий API, качество распознавания речи или работу Telegram. Запуск `sync.py`
с лимитами в config продолжает обращаться к API и писать данные — он не
заменяет эти изолированные тесты.
