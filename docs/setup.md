## Окружение и доступ

Python 3.12, плоские модули в корне; пакетной сборки и CI нет.
Версии Python и uv закреплены в [mise.toml](../mise.toml).
Зависимости объявлены в [pyproject.toml](../pyproject.toml), точные версии
зафиксированы в [uv.lock](../uv.lock). uv создаёт и обслуживает `.venv/`;
mise только активирует готовое окружение и запускает задачи.
Проверку кода без вебхука, `.env` и рабочих данных выполняйте по
[инструкции изолированных тестов](testing.md).
Команды одинаковы для Windows, macOS и Linux и выполняются из корня проекта.
Установите [mise](https://mise.jdx.dev/getting-started.html), затем:

```text
mise trust
mise install
mise run setup
```

`setup` выполняет `uv sync --locked`: создаёт `.venv` и устанавливает
зависимости приложения и группу `dev` (Ruff) по lock-файлу.
Активация вручную и установка через pip не требуются. `UV_PYTHON` передаёт uv
интерпретатор mise, `UV_PYTHON_DOWNLOADS=never` запрещает uv скачивать отдельный Python.
Файл `.python-version` не нужен: версию задаёт mise, диапазон Python 3.12 — pyproject.
Если раньше использовался `venv/`, он не переносится и не удаляется;
новые команды используют `.venv/`.

Для добавления или удаления зависимости используйте `mise exec -- uv add <package>`
и `mise exec -- uv remove <package>`. После ручной правки pyproject выполните
`mise exec -- uv lock`, затем `mise run setup`. Сохраняйте pyproject и lock-файл
в Git вместе. Секреты и параметры локальной машины в них не добавляйте;
`mise.local.toml` исключён из Git. Для VS Code выберите интерпретатор
`.venv/Scripts/python.exe` на Windows или `.venv/bin/python` на macOS/Linux.

Основной запуск:

```text
mise run start
```

`requests` нужен для HTTP-запросов; `python-dotenv` — для загрузки секретов из `.env`;
`loguru` — для [файлового логирования](operations.md#логирование).
`aiogram` нужен для [Telegram-бота](operations.md#telegram-бот) и устанавливается
вместе с остальными зависимостями. `start` запускает `bot.py`; саму выгрузку
запускает кнопка бота. Задачи setup/test/lint бота не запускают.

Создайте входящий вебхук Bitrix24 с правами `crm`, `imopenlines`,
`telephony`, `user`; для задач добавьте `task`. Секреты храните в файле `.env`
рядом с `config.py`. При импорте `config.py` вызов `load_dotenv()` загружает
значения из этого файла:

```dotenv
B24_WEBHOOK=https://<portal>/rest/<user_id>/<secret>/
ASSEMBLYAI_API_KEY=<assemblyai_key>
```

Первый параметр обязателен для Bitrix, второй — для AssemblyAI. Вебхук даёт
доступ в пределах прав пользователя и scopes. Реальные значения не публикуйте.
`PORTAL_URL` для ссылок карточек выводится из вебхука; в коде есть резервный адрес.

### Google Drive

После успешного импорта снимка в `data/sqlite3_snapshots.db` выгрузка создаёт
`export/database/sqlite3_snapshots.zip` с одним файлом базы и обновляет существующий
`sqlite3_snapshots.zip` в папке `GOOGLE_DRIVE_FOLDER_ID`. Имя без даты сохраняет
постоянный ID файла и ссылку: используется `files.update`, без удаления и
повторного создания. Если файл не найден, поиск неполон или обнаружены дубли
имени, загрузка прекращается с ошибкой.

1. В проекте Google Cloud сервисного аккаунта включите Google Drive API.
2. Положите JSON-ключ сервисного аккаунта в `key.json` рядом с `config.py`.
   Файл уже исключён из Git правилом `*.json`; не публикуйте его.
3. Дайте `client_email` из ключа доступ редактора к целевой папке и убедитесь,
   что сервисному аккаунту доступно редактирование существующего архива.
4. После обновления зависимостей выполните `mise run setup`.

`GOOGLE_DRIVE_ENABLED=True` включает отправку; для отключения задайте `False`.
`GOOGLE_DRIVE_FOLDER_ID` указывает папку назначения, `GOOGLE_DRIVE_ARCHIVE_NAME`
задаёт имя локального ZIP в `export/database/` и существующего файла на Drive,
`GOOGLE_DRIVE_CREDENTIALS_PATH` — абсолютный путь к ключу (по умолчанию в корне).
`GOOGLE_DRIVE_TIMEOUT=60` ограничивает ожидание отдельного HTTP-запроса,
`GOOGLE_DRIVE_MAX_RETRIES=3` — повторы временных ошибок чтения списка и каждой
части загрузки. Клиент использует scope `https://www.googleapis.com/auth/drive`
для обновления уже существующего файла сервисным аккаунтом.

SQLite backup снимает согласованную копию, включая зафиксированные данные WAL;
ZIP заменяется локально атомарно. Требуется свободное место под копию базы и ZIP.
Подкаталог `export/database/` отделяет ZIP базы от архивов карточек для Telegram.
Загрузка идёт частями по 8 МиБ. При сетевой ошибке база, ZIP и state/registry
сохраняются; в `data/progress.json` записывается `google_drive_status=error`,
в Telegram выводится предупреждение, в `error.log` — тип ошибки и HTTP-код без
содержимого ответа Google. Повтор следующей выгрузки вновь обновит архив.
При успехе статус — `uploaded`. Ошибка Drive не меняет код успешного завершения
локальной выгрузки. Без нового ZIP или при ошибке импорта SQLite загрузки нет.
Запуски с лимитами/ID также отправляют базу, если оба этапа включены.

При разовом вызове `google_api.upload_database` в отдельном Python-процессе
Loguru выводит в консоль (stderr) этапы копирования SQLite, сжатия, создания
клиента, поиска файла и процент загрузки каждой части, включая итоговые 100%.
При сбое сообщения Loguru содержат тип исключения и HTTP-код без ответа Google
и секретов; исключение передаётся вызывающему коду. Необработанное исключение
Python дополнительно выводит стандартным traceback. В штатном запуске через `run_cli`
эти сообщения попадают в общие файлы логов. Импорт логгера сам по себе
не загружает `config.py` или `.env`.
Итоговые 100% означают подтверждённое Drive завершение запроса; до подтверждения
процент ограничен 99%. Для ZIP меньше 8 МиБ обычно видны только 0% и 100%.

Сервисный аккаунт не создаёт новые файлы: для него нет личной квоты Drive.
Если архив удалён, восстановите его от имени пользователя и предоставьте
сервисному аккаунту доступ. [Ограничение Google](https://developers.google.com/workspace/drive/api/guides/folder),
[обновление файла](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/update),
[загрузка частями](https://developers.google.com/workspace/drive/api/guides/manage-uploads).

#### Разовая отправка без выгрузки Bitrix24

Выполняйте разовую отправку после завершения работающей выгрузки. Пример ниже
берёт уже имеющуюся базу `export/database/sqlite3_snapshots.db`, упаковывает её
в ZIP рядом и заменяет архив в целевой папке Drive. Этот файл базы должен
существовать; штатный `sync.py` сохраняет базу в `SNAPSHOT_SQLITE_PATH`
(`data/sqlite3_snapshots.db`), а в `export/database/` создаёт только ZIP.
Для отправки штатной базы замените первый аргумент `upload_database` на
`Path(config.SNAPSHOT_SQLITE_PATH)`.

Из корня проекта в bash/zsh на macOS/Linux:

```bash
mise exec -- uv run --no-sync python -B - <<'PY'
from pathlib import Path
import config
from google_api import upload_database

folder = Path(config.EXPORT_DIR) / "database"
file_id = upload_database(
    folder / "sqlite3_snapshots.db",
    folder / config.GOOGLE_DRIVE_ARCHIVE_NAME,
    credentials_path=Path(config.GOOGLE_DRIVE_CREDENTIALS_PATH),
    folder_id=config.GOOGLE_DRIVE_FOLDER_ID,
    timeout=config.GOOGLE_DRIVE_TIMEOUT,
    retries=config.GOOGLE_DRIVE_MAX_RETRIES,
)
print(f"Загружено успешно. ID файла: {file_id}")
PY
```

В Windows PowerShell тот же Python-код между маркерами `PY` передайте через
here-string: `@'` на отдельной строке, затем код, затем
`'@ | mise exec -- uv run --no-sync python -B -` на отдельной строке.

Команда использует ключ и настройки из config, вызывает Google Drive API
и заменяет удалённый файл. Bitrix24, AssemblyAI и бот не запускаются;
state/registry и `progress.json` не обновляются. Прямой вызов функции отправляет
архив независимо от `GOOGLE_DRIVE_ENABLED`: этот флаг проверяется в `sync.py`.
`--no-sync` использует уже установленное окружение без изменения зависимостей.
ZIP остаётся локально для повторной отправки. Для отправки готового ZIP без
новой архивации доступны `create_drive_service` и `replace_archive` из
[google_api.py](../google_api.py); клиент нужно закрывать через `contextlib.closing`.

#### Диагностика HTTP 403

`403 Forbidden` означает отказ операции. Drive также возвращает этот код
при некоторых ограничениях и превышении квот; точная причина определяется
по полю `reason` ответа Google. [Причины 403](https://developers.google.com/workspace/drive/api/guides/handle-errors#403_errors).
Безопасные логи приложения показывают тип исключения и HTTP-код, поэтому
одного числа 403 недостаточно для точного диагноза.

Проверьте доступ редактора для аккаунта из `client_email` в `key.json` к папке
и существующему ZIP, а также включение Google Drive API в проекте этого ключа.
Последний этап лога помогает определить отказавшую операцию:

| Последняя строка этапа | Что проверять |
|---|---|
| «ищу существующий архив» | Доступ к списку файлов, настройки API и ограничения проекта |
| «архив найден; загрузка 0%» или промежуточный процент | Право изменять найденный ZIP и ограничения загрузки |

Сообщение «клиент готов» означает создание клиента; первый запрос Drive
выполняется при поиске файла. Чтение файла или списка само по себе не
подтверждает право редактирования. Ключ, токены и полный авторизованный URL
не включайте в диагностические сообщения.

### Локальный тестовый Telegram-бот

Скопируйте [.env.dev.example](../.env.dev.example) в `.env.dev` рядом с `config.py`
и заполните `TG_BOT_TOKEN` тестового бота и `TG_CHAT_ID` разрешённого тестового
чата (несколько ID — через запятую). Для личного чата `TG_CHAT_ID` — ваш
числовой Telegram user ID. [Назначение параметра и примеры](operations.md#telegram-бот).
Файл `.env.dev` исключён из Git.
Запуск из корня проекта:

```text
mise run start-dev
```

Задача задаёт `BITRIX_ENV=dev`. В этом режиме `config.py` сначала загружает
`.env.dev`, затем дополняет недостающие переменные из `.env`. Приоритет:
**окружение процесса → .env.dev → .env**. Уже заданные в терминале Telegram-ключи
имеют приоритет и над тестовым файлом. Без `.env.dev` или без непустых
`TG_BOT_TOKEN` / `TG_CHAT_ID` до загрузки `.env` запуск останавливается:
реквизиты рабочего бота из `.env` не используются как резервные.
Для запуска из VS Code задайте `BITRIX_ENV=dev` в окружении запуска `bot.py`.
Дочерний `sync.py` наследует тот же режим и окружение.

Обычный `mise run start` при незаданном `BITRIX_ENV` использует только `.env`;
само наличие `.env.dev` его поведение не меняет. Допустимые значения
`BITRIX_ENV` — `production` (по умолчанию) и `dev`; режим выбирается из окружения
процесса до чтения dotenv-файлов.

Этот режим меняет реквизиты бота, но **не изолирует выгрузку**: Bitrix24 и
AssemblyAI по-прежнему используют общие ключи из `.env`, если они не переопределены,
а рабочие каталоги и параметры `config.py` остаются общими. Кнопка тестового
бота запускает настоящую выгрузку с сетевыми запросами и записью данных.

## Команды и побочные эффекты

Основной способ запуска — кнопка «▶️ Запустить выгрузку» в
[Telegram-боте](operations.md#telegram-бот). Бот запускает `sync.py` без
аргументов; все параметры выгрузки задаются в `config.py`. Для ручного запуска
того же процесса из корня проекта:

```text
mise exec -- uv run --locked python sync.py
```

Аргументы командной строки не поддерживаются: при их передаче процесс
завершается с ошибкой до обращения к API и формирования снимка. При
`EXPORT_TYPE="auto"` обычный запуск может быть инкрементальным.

Непустые `DEAL_IDS` / `LEAD_IDS` или ненулевые `DEALS_LIMIT` / `LEADS_LIMIT`
в `config.py` включают тестовый режим: `full` без сохранения state/registry.
Например, для ограничения обоих типов задайте `DEALS_LIMIT = 3` и
`LEADS_LIMIT = 3`. Такой запуск **вызывает API и пишет данные**: кэши, raw,
store, новый snapshot и возможный ZIP. Это не изолированный автотест.
Отключение транскрибации не запрещает скачивание записей.
Для изоляции нужны отдельные данные/пути и подмена сетевых вызовов.
Сам импорт `config.py` загружает `.env` (в dev сначала `.env.dev`) через `python-dotenv`
и создаёт каталоги данных; изолированные тесты подменяют config до импорта.

Сделки запускаются всегда: лимит лидов их не ограничивает. Для малого прогона
обоих типов задавайте оба лимита. При тесте сделок лиды пропускаются без
собственных ID/лимита; для них также нужен `PROCESS_LEADS=True`.
Настройки действуют и при запуске кнопкой бота. После ограниченного прогона
верните ID к `[]`, а лимиты к `0`, если нужна обычная выгрузка.

## Выборка и параметры

| Настройки `config.py` | Назначение / текущее значение |
|---|---|
| `DEAL_IDS`, `LEAD_IDS`; `DEALS_LIMIT`, `LEADS_LIMIT` | ID и лимиты: `[]` / `0` — без ограничений |
| `DATE_FROM` | Нижняя граница создания сущностей и выборки звонков; сейчас `2025-10-29T00:00:00+03:00` |
| `EXPORT_PERIOD_FROM`, `EXPORT_PERIOD_TO` | Явный период создания; обе границы `None` |
| `PROCESS_LEADS`; `PROCESS_ACTIVE/COMPLETED/TECHNICAL` | Лиды и все группы включены |
| `INCLUDE_COMMENTS/TASKS`; `INCLUDE_EMAILS/MEETINGS` | Комментарии/задачи включены, письма/встречи выключены |
| `OPENLINES_SESSION_MAX_PAGES` | Не более 200 страниц каждой сессии чата; при незавершённой истории — ошибка сущности. [Алгоритм и ограничения](architecture.md#история-открытых-линий) |
| `OPENLINES_SESSION_LIST_MAX_CALLS` | Не более 5000 логических запросов общего списка всех доступных сессий за прогон; превышение даёт ошибку, не переход к последней сессии |
| `TECHNICAL_STAGE_IDS/KEYWORDS`; `LEAD_TECHNICAL_STATUS_IDS/KEYWORDS` | Правила технических стадий/статусов |
| `EXPORT_TYPE`, `INCREMENTAL_OVERLAP_HOURS` | `auto` / `full` / `incremental`; перекрытие 24 ч |
| `REEXPORT_CLOSED_ON_CHANGE` | `False`: закрытые переиспользуются даже после изменений |
| `SCHEMA_VERSION`, `SNAPSHOT_TZ`, `MAKE_SNAPSHOT_ZIP` | Схема 2, `Europe/Minsk`, ZIP включён |
| `SNAPSHOT_SQLITE_ENABLED`, `SNAPSHOT_SQLITE_PATH` | После сборки ZIP сохранять конечные карточки в накопительную БД; включено, путь `data/sqlite3_snapshots.db` |
| `GOOGLE_DRIVE_*` | Архивирование накопительной SQLite и замена существующего файла; включено. [Доступ и настройки](#google-drive) |
| `FILE_BRAND`, `DEAL_COUNTRY_BY_CATEGORY`, `ZIP_NAME_TEMPLATE` | Бренд, соответствие ID воронки и страны сделки, имя архива; [правила страны](data.md#файлы-результата) |
| `REQUEST_PAUSE`, `MAX_RETRIES`, `REQUEST_TIMEOUT` | Пауза 0,2 с, 5 попыток, тайм-аут 60 с |
| `DATA_DIR`, `RAW_DIR`, `AUDIO_DIR`, `TRANSCRIPTS_DIR`, `EXPORT_DIR` | Пути через `os.path` относительно каталога проекта |
| `DEBUG_LOG_PATH`, `ERROR_LOG_PATH` | `debug.log` и `error.log` в корне проекта, независимо от текущего каталога запуска |

Полный режим применяет период только при **обеих** границах: FROM `00:00:00`,
TO `23:59:59`. `DATE_FROM` заменяет начало периода, сохраняя верхнюю границу TO.
Одиночная граница игнорируется. При `None` период не ограничивается;
предыдущая неделя автоматически не выбирается. Инкремент игнорирует FROM/TO,
но учитывает `DATE_FROM` в обеих выборках. Для всей истории — `DATE_FROM=None`.
Один явный ID запрашивается точечным `get` без фильтра дат.

Лимиты применяются к уже полученному списку **после пагинации**, поэтому
`DEALS_LIMIT = 3` не означает получение только трёх записей по API. Списочные запросы
сделок и лидов всегда выбирают стандартные и пользовательские поля (`*`, `UF_*`);
отдельного переключателя `DEAL_ALL_FIELDS` больше нет.

## Транскрибация

`sync.resolve_transcript` получает текст только через AssemblyAI при наличии
записи и `TRANSCRIBE_ENABLED=True` (включено по умолчанию).
Чтобы отключить транскрибацию, задайте `TRANSCRIBE_ENABLED=False`.

- AssemblyAI: ключ `ASSEMBLYAI_API_KEY` из `.env` через `config.py`, язык `ru`,
  подсказка 2 спикера, опрос каждые 3 с, ожидание до 900 с. Настройки `ASSEMBLYAI_*`.

По умолчанию `ASSEMBLYAI_DIRECT_URL=False`: сервер получает запись в `audio/`
и загружает файл в AssemblyAI.
Этот режим исключает попытку скачивания записи провайдером по ссылке Диска,
но серверу по-прежнему нужен доступ к аудио в Bitrix24.

При `ASSEMBLYAI_DIRECT_URL=True` провайдер получает авторизованный `DOWNLOAD_URL`
Диска; локального аудио может не быть. При ошибке — скачивание и upload.
`auth` к URL не добавляется. Оба режима передают запись внешнему сервису.

У пропущенных звонков и длительности ≤ `MIN_RECORDING_DURATION_SEC` (15 с)
файлы исключаются, само касание сохраняется. Неизвестная длительность при
наличии файла допускает запись. `DOWNLOAD_RECORDINGS=True` включает обычное
скачивание; этот флаг не запрещает загрузки во всех путях транскрибации.
Существующие аудио и тексты переиспользуются; статусы — в [data.md](data.md).
